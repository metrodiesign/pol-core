## Lessons Learned

- **Pattern**: dual-scheme / fallback-scheme policy (เช่น `producer` = ProducerSession OR tenant Bearer) ต้อง fail-closed **ทั้ง surface ไม่ใช่แค่ mutation** — reads/utility endpoint (catalog GET, logout-all) ที่ไม่เช็ค "scope bound จริง" จะรั่ว/500 ให้ caller ที่เข้ามาทาง fallback scheme. วาง bound-check ที่ระดับ group (1 filter) ไม่ใช่ไล่ทีละ endpoint. — **Why**: Codex จับว่า mutation ปลอดภัย (RequireProducerPermission fail-closes) แต่ catalog reads + logout-all ไม่เช็ค `IProducerScope.IsBound` → tenant-Bearer อ่าน RBAC catalog ได้ + logout-all deref `scope.Current` เป็น 500. ตั้ง "ทุก endpoint ที่ dereference scope ต้องผ่าน bound gate" เป็น invariant ของ shared-policy surface.
- **Discovery**: long-running dev server (`dotnet run`) ถือ binary เก่าในหน่วยความจำจน restart — `dotnet build` อย่างเดียวไม่อัปเดต process ที่รันอยู่ (scalar ไม่เห็น endpoint ใหม่ทั้งที่ source + test เขียว). ตรวจ "ระบบไม่เห็น" → เช็ค PID ที่ฟัง port (`lsof -iTCP:<port>`) ว่าเป็น build เก่าไหม ก่อนสงสัยโค้ด. ครั้งหน้าใช้ `dotnet watch run` ให้ hot-reload. — **Why**: เสีย round-trip ตามหา "ทำไมไม่เห็น" ทั้งที่โค้ดถูก — process stale ไม่ใช่ bug.
