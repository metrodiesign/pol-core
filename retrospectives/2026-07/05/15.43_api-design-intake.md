## Lessons Learned

- **Pattern**: audit ว่า "ฟีเจอร์ X มีในโค้ดไหม" ห้ามใช้ grep ชื่อ method ของ framework ตรงตัวใน Hosts อย่างเดียว — โปรเจกต์ห่อเป็น extension ชื่อของตัวเองใน BuildingBlocks (เคสจริง: หา `AddHealthChecks`/`MapHealthChecks` ไม่เจอ → บันทึกเป็น gap "ไม่มี health check" ทั้งที่มี `AddReadinessHealthChecks()`/`MapPolHealthChecks()` ห่ออยู่ + route string `/health/live` โผล่ใน BuildingBlocks.Web). ค้นด้วย concept (route string, ชื่อ domain) ทั้ง repo รวม BuildingBlocks ก่อนประกาศ "ยังไม่มี". — **Why**: gap ปลอมหลุดเข้าเอกสาร canon แล้วกลายเป็นใบสั่งงานซ้ำซ้อน — Codex จับได้บน PR ก่อนใครไปเปิด spec ทำ health check ซ้ำ.
- **Pattern**: rtk hook rewrite ครอบ `rg`/`grep` ด้วย — บนเครื่องนี้ pattern PCRE (`-P`) fail (BSD grep ข้างหลัง) และ arg แบบ `-r '$1'` ถูก mangle เป็นชื่อไฟล์; งานตรวจ regex หลายไฟล์/หลายเงื่อนไข (emoji scan, anchor check, ref inventory) เขียนเป็น `python3 - <<'EOF'` ก้อนเดียวเสถียรกว่า หรือใช้ `rtk proxy` เมื่อจำเป็นต้องใช้ tool ตรง. — **Why**: เสีย 3 รอบ retry กับ error ที่ไม่ได้มาจาก pattern ของเราเอง.
- **Pattern**: subagent อาจ misfire — จบใน ~5 วินาที, `tool_uses: 0`, คืนข้อความ canned ที่ไม่เกี่ยวกับ prompt. ก่อนเชื่อผล agent เช็ค usage metadata (จำนวน tool calls / duration) ว่าสมเหตุสมผลกับงานที่มอบ; misfire = relaunch ด้วย prompt เดิม (เพิ่มคำสั่งเปิดงานชัดๆ เช่น "start by running ls"). — **Why**: ถ้าเอาผล misfire ไปใช้ = วางแผนบนข้อมูลว่าง; จับได้เพราะดู duration+tool count ไม่ใช่เนื้อความ.
