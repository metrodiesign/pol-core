## Lessons Learned

- **Pattern**: RTK hook บีบ output ของ `git diff`/`grep` เป็น summary — pipeline ตรวจสอบที่ pipe ต่อ
  (เช่น `git diff | grep Assert`) ได้ 0 เงียบๆ ทั้งที่ของจริงมี 382 บรรทัด — **Why**: false-negative ใน
  review gate อันตรายกว่า error; งาน audit/diff-walk ต้อง dump raw ก่อน (`rtk proxy git diff ...` หรือ
  `git diff --output=<file>`) แล้วค่อย parse จากไฟล์.
- **Pattern**: wire contract ที่ flat (L8 — auth scheme id, permission key, integration-event name,
  OpenAPI scheme id) ต้องมี test pin literal อย่างน้อย 1 จุด — **Why**: sweep rename เปลี่ยน scheme id
  เงียบ 2 ครั้งใน branch เดียว (task 4 `"PlatformUserSession"`→`"Session"`) โดย suite เขียวตลอด
  เพราะทุก consumer อ้าง const; literal pin ตัวเดียวจับได้ทั้ง class ของ mistake นี้.
- **Pattern**: fail-open ของ string-derived guard เกิดซ้ำได้ทุกไฟล์ที่ derive ชื่อจาก key — task 1
  harden แค่ 2 ไฟล์ที่ระบุใน spec, `ArchitectureBoundaryTests` (ไฟล์ที่สามรูปแบบเดียวกัน) หลุดจน Codex จับ —
  **Why**: เวลาปิด fail-open pattern ให้ grep หา sibling ทุกตัวที่ derive string แบบเดียวกัน ไม่ใช่แก้เฉพาะ
  ไฟล์ที่ spec เอ่ยชื่อ.
- **Discovery**: exact-quoted-string replacement (กัน prefix corruption) พลาด composite form —
  `"Owner.Property#Money"` ใน EF snapshot รอด sweep ของ task 9 มาได้ — **Why**: rename ใน
  snapshot/designer ต้อง grep รูป annotation composite (`#Money`, `HasBaseType`, ฯลฯ) เพิ่มจาก
  ชื่อ type ตรงๆ.
- **Pattern**: subagent ห้าม dump process env เต็ม (`env`, `printenv`) — เคสจริง: teammate task 9 ทำ
  env dump หลุด `GH_TOKEN`/`GITHUB_PERSONAL_ACCESS_TOKEN`/`GEMINI_API_KEY` ค่าจริงลง transcript file —
  **Why**: transcript persist บนดิสก์/backup; ตรวจการรั่วด้วย name-only grep (นับ occurrence ของ
  `KEY=`) ไม่ echo ค่า; หลุดแล้ว = rotate ทันที ตามกฎ secrets.
- **Discovery**: teammate-per-task (Sonnet) + orchestrator verify ทุก gate เอง จับ cross-task drift ได้
  2 ครั้ง (ToTable "Keys" จาก task 5 โดย task 9, scheme "Session" จาก task 4 โดย task 10) — **Why**:
  teammate เห็นแค่ task ตัวเอง; gate ที่ rerun ของเดิมซ้ำ (has-pending-model-changes, fresh-DB,
  detector suite) คือกลไกจับ ไม่ใช่ความจำของ orchestrator.
