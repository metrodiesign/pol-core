## Lessons Learned

- **Pattern**: task-gate hook (PostToolUse) ส่งเฉพาะ `new_string` ของ edit ก้อนนั้นให้ engine scope Evidence per flipped `[x]` — flip checkbox กับ append Evidence คนละ edit = fail (hunk ที่มี `[x]` ไม่มี Evidence). ต้อง flip `[x]` + `Evidence:` + bullet จริง ≥1 **ใน edit เดียวกัน** (old_string คร่อมตั้งแต่ checkbox ถึง bullet แรก). — **Why**: เสีย 3-4 รอบ churn ต่อ task (revert→combined) เพราะ split edit; รู้ก่อน = flip ผ่านรอบเดียว.
- **Discovery**: CI "Spec trace" loop **ทุก** spec ใต้ `.ai/specs/*/` ที่มี `requirements.md` (bugfix spec ไม่มี → skip) แล้ว `|| status=1` เก็บ fail รวม exit ท้าย — spec ที่ PR ไม่ได้แตะก็ทำ PR แดงได้ (เคสจริง PR #33 แดงเพราะ `producer-google-sso` REQ-4.7 ที่ commit อื่นเพิ่มใน requirements แต่ลืมใส่ design traceability). — **Why**: อย่าเดาว่า spec-trace แดง = spec ที่เพิ่งแก้; รัน loop ทั้งชุด local หา culprit; REQ ที่เพิ่มใน requirements.md ต้องอ้างใน design.md `Requirement Traceability` + tasks.md เสมอ.
