## Lessons Learned

- **Pattern**: child table ไม่มี FK ไป route entity → handler ต้องเช็ค route entity exists ก่อนเสมอ. `AdminSessions` ไม่มี FK ไป `AdminAccounts` (`AdminSessionConfigurations.cs:19`) → `DELETE /admins/{id}/sessions/{sid}` รับ orphan/foreign id ได้เงียบ ๆ. Fix: resolve route admin ก่อน (404), แล้วค่อยเช็ค session ownership (null-or-foreign → 404). — **Why**: กัน cross-owner revoke + audit ปลอม; เป็น existing pattern เดียวกับ sessions-list/effective-perms.
- **Discovery**: codex plan-review รอบ 2 จับ 2 gap หลัง plan ดู "เสร็จ" แล้ว — orphan-session revoke (finding A) กับ security-log assertion coverage (finding B). — **Why**: adversarial 2nd round คุ้มบน security/mutation path; อย่าปิด review ที่รอบเดียวเมื่อแตะ auth/session.
- **Pattern**: Application layer โปรเจกต์นี้ logging-free (`Directory.Packages.props` ไม่ ship Logging package; `OrderPaidConsumer.cs:43` ก็ defer). structured security-log ต้อง emit ที่ HOST endpoint — handler surface field (เช่น `FamilyId`) กลับมาให้ host log. — **Why**: กันเผลอ inject `ILogger` ใน handler แล้ว build แตกเรื่อง package.
- **Discovery**: หลัง `dotnet build -warnaserror` สด → `dotnet test <proj> --no-build` หลาย project พร้อมกันได้ (parallel, ไม่ rebuild/contend). — **Why**: verify หลาย test suite เร็ว + ไม่ชน MSBuild lock.
