## Lessons Learned

- **Pattern**: shell function ที่คืนค่าผ่าน `echo "$var"` แล้วรับด้วย command substitution ทำลายข้อมูลบน dash (`/bin/sh` ของ .NET runtime image) — dash builtin `echo` ตีความ backslash escape เสมอ ปิดไม่ได้: `\t` กลายเป็น tab จริง และ `\c` ตัด output ทิ้งทั้งท่อน; refactor `CONN="...${DB_PW}..."` (assignment ตรง) เป็น `build_conn()` + `echo` จึงกลายเป็น regression ที่ตัด TLS clause หายทั้งก้อนเมื่อ password มี backslash — **Why**: กระทบ `ConnectionStrings__App` ของ prod ไม่ใช่แค่ค่าใหม่ที่เพิ่ง refactor และไม่มีชั้นไหนจับได้ (macOS `sh` เป็น bash จึงไม่ reproduce, CI ไม่แตะ path นี้) — ใช้ `printf '%s\n' "..."` เสมอเมื่อ shell function คืนค่าที่มี secret/สตริงดิบ และทดสอบด้วย dash จริงไม่ใช่ `sh` ของเครื่อง dev

- **Pattern**: test harness ที่ observe ผ่าน channel เดียว (stub print แค่ตัวแปรเดียว) ทำให้ feature ใหม่ทั้งก้อนเขียวโดยไม่มี assertion — พิสูจน์ด้วย mutation test: ลบ block ที่เพิ่งเขียนออกจากสำเนา แล้ว suite ยัง `pass=17 fail=0` — **Why**: false-green แบบนี้ปล่อย BLOCKING หลุดมาแล้วจริงในงานเดียวกัน (dash echo ข้างบน) — เมื่อเพิ่ม branch ใหม่ในสคริปต์ ต้องขยาย observation channel ของ harness ด้วย และ acceptance ของการแก้ test coverage คือ "mutation ต้องแดง" ไม่ใช่ "suite ยังเขียว"

- **Discovery**: subagent ที่รันยาวจน context ถูกบีบจะ "ลืม" งานที่ตัวเองทำไปแล้ว แล้วตีความว่ามี instance คู่ขนานมาแก้ไฟล์แข่ง (อาการ: `Edit` ล้มเพราะ `old_string` ไม่ match ทั้งที่ไม่เคยแก้ไฟล์นั้นใน "ความทรงจำ") — **Why**: ตรวจ transcript ของ agent เอง (`agent-<id>.jsonl` ใน transcript dir ของ workflow run) หา tool_use `Write`/`Edit` ต่อ path ก่อนสรุปว่ามี process ชนกัน แล้วสั่งให้ใช้ดิสก์เป็นความจริงแทนความจำ (เทียบ `git status` กับ file list ใน spec ทำเฉพาะที่ขาด) — ห้ามให้ agent หยุดรอ process ที่ไม่มีอยู่จริง

- **Pattern**: การผ่าไฟล์ SQL/config ก้อนใหญ่ต้องแยกนิยาม "ห้ามเปลี่ยน" เป็นสองชั้น — (ก) seed/data block byte-identical (verify ด้วย `diff` กับ `git show HEAD:` ไม่ใช่กวาดตา) (ข) header/THROW/PRINT ที่ hardcode ชื่อไฟล์เดิมต้อง rename ตามไฟล์ใหม่ — **Why**: ตีความ "byte-identical" แบบเหมารวมทำให้สตริง `02-external-sim:` ติดไปในไฟล์ใหม่ทั้งสอง ทำ acceptance criteria ที่ grep ชื่อไฟล์เดิม fail และทิ้ง error message ที่อ้างไฟล์ซึ่งถูกลบไปแล้ว พา operator debug ผิดทาง

- **Discovery**: แยก DB ออกคนละ SQL instance = principal ไม่ตามไปด้วย — `CREATE USER ... FOR LOGIN` พังทันที (`Msg 15007`) ถ้า instance ใหม่ไม่มี `CREATE LOGIN` ของตัวเอง และ cross-database query (`hippodb.dbo.X JOIN mammothdb.dbo.Y`) ใช้ไม่ได้อีก ต้องย้าย invariant ไปเป็น integration test ที่เปิด 2 connections — **Why**: สอง constraint นี้คือค่าใช้จ่ายจริงของการแยก instance ที่ต้องออกแบบไว้ใน spec ตั้งแต่ต้น ไม่ใช่ค้นพบตอน bootstrap แดง
