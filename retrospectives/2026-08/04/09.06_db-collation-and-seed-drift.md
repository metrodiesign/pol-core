## Lessons Learned

- **Pattern**: เพิ่ม failure mode ใหม่ (THROW) ลง SQL script ต้องไล่ audit **caller ทุกตัว**
  ว่า propagate exit code จริง — เคสจริง: collation gate ใน `01-principals.sql` จะเป็นหมันบน
  3/4 เส้นทาง (compose, GH CI, GitLab CI) เพราะ caller เรียก sqlcmd โดยไม่มี `-b` มาแต่เดิม
  (ไม่เคยมีใครสังเกตเพราะไฟล์เดิมไม่มี THROW ให้ยิง) — **Why**: class เดียวกับ false green:
  gate ที่ยิงแล้ว caller กลืน exit code = ไม่มี gate; การเพิ่ม THROW เปลี่ยนสัญญากับ caller ทุกจุด
- **Pattern**: subagent ที่หยุด "รอสัญญาณภายนอก" (Monitor รอเงื่อนไข, รอ advisor ตอบ) =
  แขวนเงียบไม่ notify — เคสจริง 4 ครั้งใน session เดียว: verifier ตั้ง Monitor รอ test ที่จบไปก่อน
  Monitor เริ่มจับ (2 รอบ), coder หยุดรอ advisor ที่คำตอบ route ไปที่ main thread (2 รอบ) —
  **Why**: main ต้องเป็นคนตรวจข้อเท็จจริงเอง (ps, ไฟล์ผลลัพธ์) แล้วปลุกด้วยคำสั่งเจาะจง
  "อ่าน output file ตรง ๆ ห้ามรันใหม่/ห้ามรอ" และ prompt งานถัดไปควรสั่ง "ห้ามตั้ง Monitor
  รัน foreground" ตั้งแต่แรกเมื่องานสั้นพอ
- **Discovery**: `ALTER DATABASE ... COLLATE` เปลี่ยนแค่ default — คอลัมน์เดิมคง collation เก่า
  ทั้งหมด และ EF dev boot (`MigrateAsync`) สร้าง DB เองได้โดยไม่ผ่าน bootstrap ⇒ "จุดสร้าง DB
  จุดเดียว" ไม่เคยจริง — **Why**: งาน collation จึงต้องเป็น reset-only + gate ใน script idempotent
  ที่รันทุก boot ไม่ใช่พึ่ง CREATE ครั้งเดียว (รายละเอียด SQL Server ลง `stack/dotnet.md` แล้ว)
