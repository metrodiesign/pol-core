# Issue body templates (spec-sync-github)

Rendered by the `/spec-sync-github` skill. Placeholders `<...>` are filled from the
spec artifacts. The leading HTML comment is a recovery marker — keep it first.
Use plain `[done]` / `[open]` (no emoji) to match the repo's no-emoji ethos.

## Epic issue

- Title: `[spec] <Title-cased feature>`
- Labels: `spec:<feature>`, `spec-epic`, `req-spine`

```markdown
<!-- spec-sync: feature=<feature> epic -->
**Spec:** `.ai/specs/<feature>/`
**Status:** <the `> Status:` line from requirements.md> · <M> tasks

Tracks the `<feature>` spec. Each sub-issue below is a cohesive, independently
verifiable slice. Progress is the sub-issue checklist GitHub renders above.

### Requirement coverage (REQ spine)

| Task | Satisfies REQ | Done = |
| ---- | ------------- | ------ |
| #<task-issue> <headline> | <Satisfies IDs> | <short done-definition> |
| ... | ... | ... |

_Generated by `/spec-sync-github`. Do not edit by hand — re-run the command._
```

For a bugfix spec (no `## REQ-N:` headings) omit the "Requirement coverage" table.

## Sub-issue (one per task)

- Title: `[<feature>] <N>. <headline>`
- Labels: `spec:<feature>`, `spec-task`
- State: `[x]` -> closed, `[ ]` -> open

```markdown
<!-- spec-sync: feature=<feature> task=<N> -->
**Epic:** #<epic-issue> · **Task <N>** of spec `<feature>`

**Scope / done =** <the "— <scope + done>" portion of the task line, verbatim>

**Satisfies:** <REQ/B IDs from the Satisfies: line>
**Depends on:** <each Depends-on task number mapped to its #NN via the manifest, or "none">
**Verify:** <the Verify: line>

**Status:** [done] | [open]

<details><summary>Evidence</summary>

<the Evidence block verbatim, or "n/a — not yet implemented">
</details>

_Source of truth is the spec; this issue mirrors it. Generated by `/spec-sync-github`._
```
