# Browser-verify / probe recipes

> โหลดเฉพาะช่วง verify: spec-implement สั่ง Read ไฟล์นี้ก่อนเริ่ม browser-based
> verification ทุกครั้ง. บทเรียน probe/Playwright/MCP ที่ promote จาก retrospectives —
> implementation patterns เฉพาะ UI framework อยู่ใน stack reference ของโปรเจกต์ (ถ้ามี, path-scoped).
> Keep lean, prune stale.

## Viewport / environment

- **Pattern**: ก่อนเชื่อผลที่ viewport boundary ยืนยัน `document.documentElement.clientWidth === target` เป๊ะทุกครั้ง — ตั้ง viewport = breakpoint ตรงๆ ก่อน แล้วชดเชย scrollbar **เฉพาะเมื่อ clientWidth != target**: headless Chromium = overlay scrollbar 0px ไม่ต้องชดเชย, Playwright บน window จริง scrollbar กิน ~15px (768 -> clientWidth ~753 ต้องตั้ง 783). — **Why**: ค่าชดเชยไม่ universal ข้าม environment — สูตร +15 บน headless over-compensate เป็น 783 จริง = ทดสอบผิดจุด; ไม่ชดเชยบน window จริง = เทสต์ที่ 753 พลาดบั๊กที่ 768 (off-by-one breakpoint จับได้เฉพาะค่าเป๊ะ).
- **Discovery**: chrome-devtools MCP `resize_page` ผูกกับหน้าต่าง OS จริง — macOS Chrome มี **min window width ~485px**, ตั้ง 375 ไม่ลง (`clientWidth` ได้ 485, `innerWidth` 500). ทดสอบ mobile 375 จริงต้องใช้ `emulate` viewport `375x812x2,mobile,touch` (CDP `setDeviceMetricsOverride`) ไม่ใช่ resize. ยืนยัน `document.documentElement.clientWidth === 375` ก่อนเชื่อผล overflow/grid-col. — **Why**: REQ บังคับ verify 375; resize อย่างเดียวรายงาน "mobile ผ่าน" บน 485 ที่ไม่ใช่ขนาดจริง = false-pass ขอบล่าง (grid อาจยัง 2-col ที่ 485 แต่ spec ต้อง 1-col ที่ 375).
- **Pattern**: ถ้าโปรเจกต์ ship UI ให้ browser-verify interaction กับ **production build / target runtime ของโปรเจกต์** เสมอ (build แล้ว serve ด้วย production command ของ UI framework นั้น ไม่ใช่ dev server) แล้วชี้ Playwright ไป `http://127.0.0.1:<port>/` (IPv4 ไม่ใช่ `localhost`). ก่อนเชื่อผลคลิก probe hydration ของ UI framework (เช่นบน framework ที่มี client-side hydration: marker บน element ที่บอกว่า hydrate แล้ว); ไม่มี = ยังไม่ hydrate = คลิก no-op (ไม่ใช่บั๊ก UI). หลังแก้โค้ดทุกครั้ง **rebuild** ก่อนเทสซ้ำ. — **Why**: dev server บางตัว HMR/live-reload ถูก proxy พัง -> page โหลดแต่ client ไม่ hydrate -> false-negative; `curl -sf ... 200`/build เขียว พิสูจน์แค่ "มีอะไรรันอยู่" ไม่ใช่ "โค้ดล่าสุด" (เคยมี app อื่นจอง port เดิม + serve build เก่า).
- **Discovery**: ทั้ง playwright MCP (ไม่ expose emulateMedia) **และ** chrome-devtools MCP `emulate` (มีแค่ colorScheme/cpu/network/geo/viewport/userAgent — **ไม่มี `prefers-reduced-motion`**) ทำ reduced-motion ไม่ได้ตรงๆ. workaround ที่ใช้ได้จริง: chrome-devtools `navigate_page` + `initScript` stub `window.matchMedia` คืน `{matches:true, addEventListener(){}, ...}` เมื่อ query มี `prefers-reduced-motion` (รันก่อน page script) -> JS autoplay gate (`matchMedia(...).matches`) เห็น true -> ไม่ตั้ง `setInterval`. **ยืนยัน gate จริงไม่ใช่ slider ตาย**: control run ไม่ stub ต้อง advance (`aria-selected` 0->1 ใน ~7s); stubbed run ต้องนิ่ง (0->0 ใน ~6.5s). อ่าน active slide ผ่าน `aria-selected` + `await setTimeout` ครอบ ≥1 interval ใน async eval. (colorScheme/print ยังใช้ chrome-devtools `emulate` ได้.) — **Why**: lesson เดิม "สลับไป chrome-devtools emulate" ผิดสำหรับ reduced-motion (tool ไม่มี param) -> จะติดตัน; initScript matchMedia stub เป็นทางเดียวทดสอบ JS reduced-motion gate ผ่าน MCP. อย่าอ้าง "logic untouched" เป็น evidence — บันทึก gap ถ้าทำไม่ได้.

## UI framework interaction probes

> recipe ในหมวดนี้ใช้คำว่า "React" เป็นตัวอย่าง framework ที่มี client-side hydration + synthetic event delegation; ถ้าโปรเจกต์ใช้ UI framework อื่น ปรับ marker/event ตาม model ของ framework นั้น — invariant (แยก action/read, hover-persist, native setter, hit-test ต่อเนื่อง) ยังเหมือนเดิม.

- **Pattern**: ตรวจ interaction ผ่าน browser_evaluate กับ controlled component ของ UI framework แยก "action (click/dispatch)" กับ "read DOM" เป็นคนละ evaluate call. — **Why**: framework re-render async; อ่านใน call เดียวกับ click ได้ค่าเก่า (race) -> เกือบรายงานว่า UI พังทั้งที่ logic ถูก.
- **Pattern**: ทดสอบ autoplay/pause carousel ใน Playwright — `el.dispatchEvent(new MouseEvent('mouseenter'))` **ไม่ trigger** synthetic `onMouseEnter`/`onFocus` ของ framework ที่ delegate event (เช่น React สังเคราะห์จาก native `mouseover`/`mouseout` delegation ที่ root ไม่ใช่ฟัง mouseenter ที่ dispatch มือ) -> pause ไม่เกิด -> autoplay แทรกระหว่าง action↔read ทำ wrap/index test ได้เลขผิด (false negative ว่า slider พัง). ใช้ `page.hover()` จริงสำหรับ pause-on-hover, และ `page.emulateMedia({reducedMotion:'reduce'})` ปิด autoplay ให้ทดสอบ wrap/keyboard/dots deterministic (+ verify REQ reduced-motion พร้อมกัน). autoplay เป็น JS (`setInterval`) ต้อง gate `matchMedia('(prefers-reduced-motion: reduce)')` ใน JS เอง — global stylesheet คุมแค่ transition ไม่หยุด interval. — **Why**: dispatch มือทำให้สรุปว่า logic พังทั้งที่ test method ผิด; reduced-motion emulation ยิงนัดเดียวได้ทั้ง deterministic + REQ reduced-motion.
- **Discovery**: ตรงข้ามกับ mouse-enter — `el.dispatchEvent(new KeyboardEvent('keydown',{key:'Escape',bubbles:true}))` **trigger synthetic `onKeyDown` ได้จริง** (framework ที่ delegate keydown ที่ document root เช่น React). ดังนั้น verify ESC/keyboard ใน `browser_evaluate` ใช้ dispatched keydown ได้ (เปิดด้วย `page.hover()` ก่อน, dispatch ESC, อ่าน `aria-expanded`/`activeElement` แยก call): ปิด+คืน focus+ไม่เปิดซ้ำ (suppressOpenRef) ครบ. สรุปกฎ: keydown dispatch=ได้, mouseenter/mouseover dispatch=ไม่ได้, hover/focus-open=`page.hover()`. — **Why**: เลี่ยงเดาว่า ESC handler พังทั้งที่ method ถูก; mix dispatch (keyboard) + page.hover (pointer) ตามชนิด event ที่ framework ฟังจริง.
- **Pattern**: set controlled `<select>`/`<input>` value ของ framework ใน eval ต้องใช้ native setter ของ **prototype ที่ตรง tag** (`Object.getOwnPropertyDescriptor(HTMLSelectElement.prototype,'value').set` vs `HTMLInputElement.prototype`) แล้ว dispatch `input`+`change` — ผิด prototype = framework state ไม่ขยับ. compose หลาย state ใน eval เดียวด้วย functional update (click dot0 → click prev → index=len-1) อ่านผลใน call ถัดไป. — **Why**: verify controlled form/slider บน production build ผ่าน native setter ไม่งั้น false-negative ว่า component พัง.
- **Discovery**: MCP `browser_evaluate` — `element.focus()` ใน eval **ไม่ persist ข้าม call** (เปิด state ด้วย focus แล้วอ่านรอบถัดไป -> state หาย/ปิด) แต่ `page.hover()` **persist**. เปิด dropdown/menu ที่ต้องวัดข้าม call ใช้ `page.hover()` ไม่ใช่ `focus()` ใน eval; อย่าปล่อยเวลายาวระหว่าง hover-open กับ read (hover-drift ทำ state หลุด -> false-alarm "พัง"). อ่าน `aria-expanded` หลัง action แยก call (framework async) แต่ติดกระชับ. — **Why**: เสียรอบเดา "ทำไม dropdown ไม่เปิด" เพราะ focus ใน eval context ไม่ค้าง; hover เป็นช่องเปิด state ที่เสถียรกว่าสำหรับ verify ข้าม call.
- **Pattern**: dropdown hover-bridge verify: `elementFromPoint` กลาง gap = wrapper โปร่งใส (`bg rgba(0,0,0,0)`) **และ** `li.contains(elAtGap)===true`; traversal `page.hover(trigger)` -> `page.hover(menuitem)` แล้วอ่าน `aria-expanded` (แยก call) ยัง `"true"` + menuitem `elementFromPoint`=`A` (ไม่ถูกบัง). — **Why**: hit-test ต่อเนื่องผ่าน gap คือ invariant ของ bridge; ดู implementation ใน stack reference ของโปรเจกต์ (เช่น padding บน absolute wrapper).
- **Discovery**: Playwright strict mode reject selector ที่แมตช์ >1 element (ฟอร์มมี 2 `input[type=number]` -> `:nth-of-type(1)` ยัง violation เพราะนับ type ใน parent ต่างกัน) -> เจาะด้วย attribute selector ที่ unique (เช่น `input[id$="-fieldA"]` / `input[id$="-fieldB"]`) แทน positional. — **Why**: positional/nth selector เปราะกับฟอร์มหลาย field ชนิดเดียว; เสียรอบ verify เพราะ selector ก่อนถึงเนื้อ test.

## Overflow / visual / a11y probes

- **Pattern**: วัด horizontal overflow ด้วย `document.documentElement.scrollWidth > innerWidth` เป็น primary เสมอ; ค่อยใช้ `getBoundingClientRect().right > innerWidth` ระบุ culprit _หลัง_ ยืนยันมี scroll จริง และ **ตัด svg/rect/circle/path/g ออก** (SVG `preserveAspectRatio="slice"` รายงาน box เกิน viewport เสมอแม้ parent `overflow-hidden` = false positive). culprit เป็น component ของ task อื่น = รายงาน อย่าแก้เงียบ (ยกเว้น task page-wide audit เอง เช่น responsive/a11y — own REQ overflow ทั้งหน้า แก้ได้). culprit probe **ตัด ancestor ที่ clip ออกด้วย** (เดิน parent หา `overflow-x: hidden/clip/auto/scroll` -> เจอ = ignore) รายงานเฉพาะ node "unclipped" — slider/carousel ที่ตั้งใจเลื่อนมี `.right` โต (เช่น 2139px) แต่ถูก clip = ไม่ทำ document overflow จริง. — **Why**: bounding box เดี่ยวไม่ใช่เครื่องมือวัด overflow (false positive จาก SVG geometry + slider clip ทำเกือบไล่แก้ผิดที่); overflow ไม่บอกที่มา เดาแล้วแก้ผิดไฟล์ = scope creep + พัง task boundary (เคสซ้ำ: overflow 768 เป็นของ UtilityBar task 4 ไม่ใช่ section task 5/6).
- **Pattern**: overflow ซ่อนได้ที่ viewport **นอก acceptance set** (เช่น 1024 ขณะ spec ตรวจ 375/768/1440) แม้ทุก spec viewport เขียว — desktop nav เริ่มที่ `lg:`=1024 แต่ element ข้างเคียง (UtilityBar icon links) เบียดขวาพอดีที่ขอบ. เมื่อ culprit เป็นของ task อื่น ยืนยัน pre-existing ด้วยวัด overflow ตอน feature ของตัวเอง **ปิด/ไม่ทำงาน** (dropdown ปิด -> ยัง `scrollWidth>clientWidth` = ไม่ใช่ของเรา) แล้ว **รายงาน ไม่แก้เงียบ** (task boundary). — **Why**: acceptance viewport ไม่ครอบทุกจุด off-by-one; แยก regression ของตัวเองจาก pre-existing ก่อนสรุป กันไล่แก้ผิดไฟล์ + scope creep.
- **Discovery**: verify focus-ring (และ pseudo `:focus-visible` ใดๆ) ใช้ **keyboard Tab จริง** (`browser_press_key Tab` → อ่าน `document.activeElement` outline/boxShadow) ไม่ใช่ programmatic `el.focus()` — ใน headless Chromium `.focus()` ทำ `:focus-visible` heuristic เพี้ยน: `el.matches(':focus-visible')` คืน true แต่ `getComputedStyle(el).outline` คืน UA default ปลอม (`1.5px solid currentColor`) สลับไปมาระหว่าง element (อ่าน element ที่ focus ตรง=ค่าถูก, อ่านตัวที่ไม่ใช่ active=ปลอม). — **Why**: เกือบไล่แก้ "การ์ด ring ไม่ขึ้น" ทั้งที่ CSS ถูก (measurement artifact); Tab จริง trigger :focus-visible เสถียร พิสูจน์ outline ครบทุกชนิด button/link/input/chip/card.
- **Pattern**: inline SVG ที่มี objective anchor opacity (≥X) ต้องคุม **effective opacity ทั้ง ancestor chain** — `<g opacity="a">` ครอบ `<path opacity="b">` = a×b. แก้แค่ path attr ให้ผ่าน verify (อ่าน attr=b) แต่ตาเห็นจางจริง (a×b). ตั้ง ancestor `<g>`=1 (หรืออ่าน computed) แล้ว verify ทั้ง path attr และ g attr. — **Why**: verify table ที่สั่ง "อ่าน SVG attr ≥0.35" จะ false-pass ถ้า `<g opacity="0.9">` ครอบ (effective 0.36 borderline/จางกว่าตาเห็น); multiplicative opacity ของ parent มองข้ามง่ายเพราะ probe อ่าน node เดียว.
- **Pattern**: contrast-audit probe ที่ไต่ ancestor หา effective bg ต้องอ่าน **ทั้ง `backgroundColor` และ `backgroundImage`** — พื้นเข้มหลายที่ทำด้วย gradient ซึ่ง `backgroundColor` = `rgba(0,0,0,0)` -> probe ที่อ่าน backgroundColor อย่างเดียว "ทะลุ" ไปเจอ light container ใต้ -> รายงาน white-on-dark h2 เป็น ratio 1.07 (ปลอม ทั้งที่จริง ~13). ก่อนสรุป contrast fail dump ancestor chain ดู `backgroundImage`; เจอ gradient/image = bg จริงเป็นสีนั้น ไม่ใช่ fall-through. — **Why**: เกือบรายงาน a11y defect ปลอม + แก้สี text ที่ถูกอยู่แล้ว. คลาส false-positive เดียวกับ SVG-geometry overflow (probe อ่าน property ไม่ครบ -> สรุปผิด); text บน gradient/รูป verify ด้วยตา/ระบุ bg layer ไม่ใช่ getComputedStyle node เดียว.
